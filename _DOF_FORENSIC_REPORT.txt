【一】模型实建自由度 = 2（铁证：URDF 文本，不是推断）
--------------------------------------------------------------------------------
文件 matlab2609/simscape/exo_real.urdf：

  <link  name="base">
  <link  name="leg_L">      <joint name="hip_L" type="revolute"> parent=base child=leg_L
  <link  name="leg_R">      <joint name="hip_R" type="revolute"> parent=base child=leg_R

  两关节参数完全相同：
    origin xyz = (0.113697402, 0.000239573, -0.052968076) m = (113.70, 0.24, -52.97) mm
    axis   xyz = (-0.002126699, -0.999956730, -0.009056215)      ≈ -Y

  含义：
   · 模型里腿相对腰只能绕「左右方向轴(Y)」转动 = 前后摆(屈伸)。
   · 没有任何绕前后轴的转动(内收/外展)，也没有绕腿长轴的转动(内/外旋)。
   · 左右两个 hip 关节原点相同 => 模型里左右腿共用同一条髋轴线。
   · leg_L / leg_R 各自是一个刚体网格，CAD 里任何可动结构都被冻结成刚体了。

  与 _hip_axis.json 相互印证（独立算法得到同一结论）：
    最佳轴来自 电机_出轴，n_coaxial=573、覆盖 13 个零件、含 leg_L/leg_R/motor_L/motor_R
    point = (113.645, -24.238, -53.190) mm
    dir   = (0.002127, 0.999957, 0.009056)      ≈ +Y
  → CAD 的髋轴就是「电机输出轴所在的 Y 线」。

  坐标系（来自 URDF 的 leg_L / leg_R 视觉原点）：
    X = 前(+)/后(-)     Y = 左(+)/右(-)     Z = 上(+)/下(-)
    leg_L 在 y≈+0.16 m，leg_R 在 y≈-0.16 m。
    实测分组 Y 范围：腿部设计_左 y∈[103.7, 217.3] mm，腿部设计_右 y∈[-216.9, -105.2] mm。
  → 所以「向内旋转」= 让腿绕一个落在 X–Z 平面内的轴转，从而往 ±Y 方向摆。

【三】判读：B 组里只有两处是真「轴/孔配合」，其余不算
--------------------------------------------------------------------------------
  1) 髋部 / 电机侧（距髋 53~55 mm）——最像真铰链
       电机_轴            Ø8 轴
       电机_黄铜轴套8_10_18  Ø8 内孔 / Ø10 外径  ← 这是「采购的滑动轴承」，不是随手画的孔
       电机_出轴           Ø8.06 / Ø16
       电机_片形腿杆连接件    Ø10 / Ø16
     装了一颗黄铜轴套 => 工程上这就是一根横向铰链销，是整套几何里唯一带「标准轴承」的
     转动特征。它的轴线方向 ≈ (0.445, 0, 0.895)，落在 X–Z 面内，与髋轴严格垂直(≈90.0°)。

  2) 腿部绑缚侧（距髋 339~360 mm）
       腿部_滑块_双键  Ø6 / Ø7 / Ø8
       腿部_轴盖      Ø6.5 / Ø8 / Ø10.1
       腿部_绑缚      Ø22 / Ø26
     但同一区域还并排出现 埋头螺丝_M3_6 / 平头螺丝_M3_8 / 螺丝_M3_4（r 全 =3.0），
     所以这里更像「夹紧 + 可调」而不是一根干净的轴承销。

  3) 排除项（重要，否则会数出一堆假关节）
       · 所有 r = 1.25 / 1.5 / 1.6 / 1.95 / 2.75 的面 = M3 沉头孔/过孔/注塑螺母 =>
         螺栓紧固的刚性连接，不是运动副。
       · 腿部_绑缚 的 r=75 / 75.3 / 75.5 = 绑带环的外形弧；电机 的 r=22 = 电机法兰外圆。
         这两个是零件轮廓，不是孔。
       · 同一零件（如 电机_出轴）能同时出现在 A 组和 B 组：说明该零件上既有沿髋轴的
         主圆柱（法兰/轴端），也有一个横向的圆柱接口（横向轴/衬套孔）。

  4) 「滑块 / 滑轨」这一族是【移动副】，不是旋转副
       CAD 里有：腿部_滑块_双键 + 腿部_滑轨_片形 + 腿部_按键_双 + 腿部_滑轨挡片。
       名字即「滑块 / 滑轨 / 按键」，配合半径只有 0.5 / 1.0 / 1.2 mm（=键槽/卡扣），
       方向 ⊥ 髋轴。这是【沿腿杆的直线滑动调节 + 双键防转】，是平移自由度，
       不会有「向内旋转」。

【四】结论（直接回答「这个结构应该是可以向内旋转的」）
--------------------------------------------------------------------------------
  · 你说得对：CAD 几何里确实存在「轴线垂直于髋轴」的配合，绕它转就是腿往内侧摆。
    几何上成立且带真半径的只有两处候选：
      (i)  髋部/电机侧的横向 Ø8 黄铜衬套轴系（距髋 ~55 mm）—— 最强，因为有标准轴承；
      (ii) 绑缚区的横向销（距髋 ~345 mm）—— 较弱，混着大量 M3 螺丝。
  · 但两种都没有被建模：exo_real.urdf 里 leg_L/leg_R 各是刚体，只有 hip_L/hip_R 一个
    revolute。CAD 里若有这个可转结构，导入 Simscape 之后被【冻结】了。
  · 另外必须提醒：README 里对论文的复现口径写明是 2-DOF（左髋+右髋）。
    加自由度会偏离这批实验的 scope。

【五】若确认要把它建成一个自由度（暂不动手，等你点头）
--------------------------------------------------------------------------------
  1. urdf/import 侧：把 leg_L 拆成两段（销轴前 / 销轴后），在 exo_real.urdf 增加
     <joint type="revolute">，origin=销轴位置、axis=销轴方向；重新 smimport 并重建 harness。
  2. 分析侧：+exo2609 必须同步增加一个广义坐标，否则 compare_simscape_vs_analytical
     会因自由度数目不一致而 rms/range 全部对不上。
  3. 若是被动关节：只加 joint、不加驱动（或挂弹簧/阻尼）。
  4. 改动前先跑一次基线对比，留存档，便于回归。
