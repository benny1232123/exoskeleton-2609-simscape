## 二、材料实验：SW 吃不吃赋进去的密度？

### 2.1 方法（可复现）

只动**一个**零件、只改**内存**、不存盘、不关任何文档：

1. `sw.GetDocuments` 找到 `电机_轴.SLDPRT`；
2. 经 `IModelDocExtension.CreateMassProperty2()` 读基线（质量/体积/密度）+ `MaterialIdName`；
3. `IModelDoc2::SetMaterialPropertyName2('默认','SolidWorks Materials','1023 碳钢板 (SS)')`；
4. 再读一次质量属性；
5. **回滚**：`SetMaterialPropertyName2('默认','','')`，再读一次并**逐位比对基线**。

### 2.2 实测数据

| 量 | 赋材质前 | 赋材质后（`1023 碳钢板 (SS)`） |
|---|---|---|
| `MaterialIdName` | `''`（无材质） | `'solidworks materials\|1023 碳钢板 (SS)\|82'` |
| `Mass` | `0.00150609303965569 kg` | `0.0118348791538094 kg` |
| `Volume` | `1.50609303965569e-06 m³`（= 1506.0930 mm³） | **同左，未变** |
| `Density` | `1000.000000 kg/m³` | **`7858.000032 kg/m³`** |
| **质量比** | — | **7.858000** |
| **体积比** | — | **1.000000** |

材料库真值：`1023 碳钢板 (SS)` 的 `DENS = 7858.000032`（读自
`solidworks materials.sldmat`，UTF-16 `<physicalproperties><DENS value=.../>`）。

⇒ **质量比 7.858000 恰等于密度比 7858.000032/1000**，体积丝毫未动
⇒ 这是**纯粹的密度效应**，SW 会严格按材质密度重算质量。
⇒ 所以「在 SW 里批量赋材料 → 导出即得真实质量」这条路**机制上成立**。

### 2.3 回滚证据（本次实验没有改动任何 CAD）

```
SetMaterialPropertyName2(blank) -> MaterialIdName=''
MaterialIdName = ''
Mass   = 0.00150609303965569 kg   (baseline 0.00150609303965569)
Density= 1000.000000 kg/m3
REVERT_OK = True
```
质量回到基线**逐位相同**（`0.00150609303965569`），材质名清空。

> ⚠ 注：`EditUndo2` 在晚期绑定下取不到（`invoke failed dispid=66281`）；
> 起作用的回滚是**把材质名设成空串**。

### 2.4 ⚠ 但这条路的"独立性"要打折

把**我们自己猜的密度表**批量写进 SW、再导出，得到的是一个
**把我们的假设绕 SW 一圈又还给我们**的"基准" —— 它**不是独立证据**。
它只能证明「管道通了」，**不能证明密度猜对了**。

⇒ 想要**真正独立**的质量基准，唯一硬证据仍然是 **称重**（实物单件质量 ÷ 已知体积）。
   好消息：几何已经被 SW 内核对过（体积一致），所以**密度是唯一未知量**，
   **称几件关键件就能锁定整机质量**（见第三节）。

## 四、文档值 0.304833 kg 的复现（对账闭环）

文档里 `leg_L m = 0.304833 kg`（`plant_params.csv` / `exo_real.urdf` / `2609_report.html`）
一直是**按「摆动件分组」的另一口径**（`exo_real_report.txt`: `n_solid=35`）。
本轮把口径显式化：

| 口径 | 质量 | 与文档值偏差 |
|---|---|---|
| 19 个唯一零件，每件算一次 | 0.296227 kg | −2.82% |
| **19 零件 × 35 实例（SW 体积 × 我方密度表）** | **0.304991 kg** | **+0.0518%** ✅ |

实例多重度（取自 `腿部设计_左.fixed.xml` 的 35 个 `<Instance>`）：

```
腿部_平头螺丝_M3_8              ×4
腿部_埋头螺丝_M3_6              ×4
腿部_埋头螺丝_M3_8              ×4
腿部_法兰注塑螺母_M3_6.3_4.6_5.5   ×4
腿部_按键_双                   ×2
腿部_顶丝_M4_4                 ×2
腿部_滑轨挡片                   ×2
腿部_螺丝_M3_4                 ×2
其余 11 种                      ×1
                       ------------
                        合计 = 35  ✓
```

⇒ **文档值被复现到 0.052%**，残余 0.05% 来自几何差异
（`腿部_腿杆_片状V5` −0.179%、`腿部_滑轨_片形` −0.042%，均为自由曲面件的两内核差异）。
⇒ 这条把「我方解析链 → 密度表 → 分组口径 → 文档参数」整条链**自洽性钉死了**。

## 五、本轮学到的 SolidWorks COM 硬知识（晚期绑定）

血泪堆出来的，直接抄：

| 要点 | 说明 |
|---|---|
| **`PyIDispatch.Invoke` 的正确形式** | `Invoke(dispid, lcid, wFlags, bResultWanted, *args)` —— **至少 4 个实参**。写成 3 个会报 `not enough arguments (at least 4 needed)` |
| **别剥 `_oleobj_`** | `PyIDispatch` 自己有 `_oleobj_`，剥完拿到的是裸 OLE 对象，`Invoke` 签名不一样 |
| **`GetIDsOfNames` 返回 int** | 不是元组；直接当 dispid 用（写成 `ids[0]` 会 `'int' object is not subscriptable`） |
| **没有 `GetTypeInfo`** | `GetTypeInfo()` 报「无效索引」→ 别指望枚举成员；用 `GetIDsOfNames` 逐个探 |
| **读质量属性的唯一可用组合** | `doc.Extension`(dispid 66306, GET) → `CreateMassProperty2`(dispid 313, **flag=DISPATCH_PROPERTYGET**, 无参) → `Mass`/`Volume`/`Density`/`CenterOfMass` |
| **`SetMaterialPropertyName2(cfg, db, name)`** | dispid 142；`db='SolidWorks Materials'`；成功后 `MaterialIdName` 形如 `'solidworks materials\|<名>\|<matid>'` |
| **清材质 = 传空串** | `SetMaterialPropertyName2('默认','','')`；`EditUndo2` 晚期绑定取不到 |
| **`GetMaterialPropertyName2` 要 byref** | `VARIANT(VT_BYREF\|VT_BSTR,'')` 才能拿到输出参数 |
| **材料库可离线读** | `sw.GetMaterialDatabases`（**属性**，不是方法）；`.sldmat` 是 **UTF-16** XML，密度在 `<physicalproperties><DENS value=.../>` |
